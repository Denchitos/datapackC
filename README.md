# DatapackC
Компилятор с собственного DSL в .mcfunction для создания датапаков *Minecraft*

## Структура программы

Код для datapackC делится на следующие секции
```text
  <файл>
  - namespace - пространства имён
  - objective - таблицы scoreboard
  - def < имя функции > - функции
  - inline < имя функции > - то же функции ( разница будет объяснена в отдельном разделе )
  - storage - nbt-структуры
```

### **namespace**

---

namespace - ключевое слово для объявления пространства имён где компилятор будет создавать функции

---

Например, вы в файле напишите следующее
```text
  namespace global:dp/tests
```
Будет означать что компилятор будет создавать все далее объявленные функции в таком виде
```text
datapack/
└── data/
   └── global/
      └── function/
         └── dp/
            └── tests/
                ├── func_1
                ├── func_2
                ├── ...
                └── func_n
```
Т.е это просто префикс, который вы указываете перед именем функции при её вызове в майнкрафт.

Например функция func_k будет вызываться в майнкрафте так
```text
  function global:dp/tests/func_k
           └─────────────┘
            - это то, что вы указали после namespace
```

Пример других корректных пространств имён
```text
  namespace global:dp
  namespace minecraft
  namespace minecrst:functions/print
```
... и не корректных
```text
  namespace global:dp/ # <-- оканчивается на '/', это недопустимо
  namespace minecraft/dp # <-- после первого слово обязано быть ':'
  namespace minecraft: # <-- после ':' должно идти следующее слово
```

---

**И да, комментарии в моём языке обозначаются через '#'. Комментироваться будет всё от '#' до конца строки**

---

## **objective**

---

objective - ключевое слово, которое указывает создать scoreboard в *Minecraft*

---

Например, вы в файле напишите следующее
```text
  objective myscore
```
И что это значит?

Предположим вы создаёте objective в пространстве global:dp
```text
  namespace global:dp

  objective myscore
```

Это означает что в датапаке будет создан следующий scoreboard
```text
  scoreboard objectives add global.dp.myscore dummy
```
Это строка будет добавлена в load.mcfunction файл - который будет запускаться при загрузке мира *Minecraft* или после /reload

---

Как работать с этими objectives будет показано в разделе ниже

## **Как выглядит исполняемый код**

---

Я решил что мой DSL должен быть статически типизируемым.

---

### Базовые типы

---

Пока есть следующие базовые типы.

| Тип | Задача |
|---|---|
| score | Это обычная переменная реализованная на scoreboard - через неё вы можете выполнять операции '*', '/', '-', '+', '%', а также '==' , '!=' |
| score_bool | Булевая переменная, в неё вы можете записать true/false. Поддерживает операции '&&', '\|\|' |
| string | Это nbt-переменная ( значит что хранится как data ), Её можно копировать, а также в неё можно присвоить строковый литерал |
| int | Это nbt-переменная, Её также, пока что, можно копировать или присвоить числовой литерал |
| selector | Это на самом деле не-совсем тип, Но работает схожим образом. В него можно записать сырой *Minecraft*-селектор вида @a\[...\] или @s @n @r @p , нужен как для работы с objective а также для вызова фукнции от лица сущности |
| objective | Это особый тип - он объявляется только в глобальном пространстве через objective как рассказано выше. Его также, как и селектор, нельзя передавать в функции не макросом. Нужен при работе со scoreboard |

---

Работать можно с только объявленными переменными:

нельзя просто написать
```text
  a = 5
  a = 4 + a
```
Нужно обязтельно так
```text
  let a : score = 5
  a = 4 + a
```

Что такое let

let это ключевое слово для объявления переменных, выглядит это так
```text
  let <имя переменной> : <тип переменной> = < выражение >
```
Нюансы

Обязательно при создании переменной её нужно инциализировать. Иначе просто вылетит сообщение об ошибке компиляции.

Тип переменной на самом деле указывать нужно не всегда. Компилятор может сам их вывести по инициализатору.

- Например - ***"let a = 5"*** - само выведет тип для переменной а как score
- Или - ***"let b = a"*** - переменная 'b' будет иметь тот же тип что и переменная 'a'
- Но если создавать int от какого-то числа, то его всё же придётся указать - ***"let с : int = 5"*** - если тип не указать, то он выведется как score
- И снова вспоминаем что если написать ***"let x = c"***, то тип будет int. Так как тип инициализатора известен - int
- ***" let d = "Hello world" "*** сам выведется тип string
- ***" let f = @s "*** - у 'f' тип будет selector
