# DatapackC
Компилятор с собственного DSL в .mcfunction для создания датапаков *Minecraft*

## Структура программы

Код для datapackC делится на следующие секции
```text
  <файл>
  - namespace - пространства имён
  - objective - таблицы scoreboard
  - def < имя функции > - функции
  - inline < имя функции > - то же функции ( разница будет объяснена в отдельном разделе )
  - storage - nbt-структуры
```

### **namespace**

---

namespace - ключевое слово для объявления пространства имён где компилятор будет создавать функции

---

Например, вы в файле напишите следующее
```text
  namespace global:dp/tests
```
Будет означать что компилятор будет создавать все далее объявленные функции в таком виде
```text
datapack/
└── data/
   └── global/ <--- указано в namespace
      └── function/
         └── dp/ <--- указано в namespace
            └── tests/ <--- указано в namespace
                ├── func_1 |
                ├── func_2 | Это всё ваши
                ├── ...    | функции
                └── func_n |
```
Т.е это просто префикс, который вы указываете перед именем функции при её вызове в майнкрафт.

Например функция func_k будет вызываться в майнкрафте так
```text
  function global:dp/tests/func_k
           └─────────────┘
            - это то, что вы указали после namespace
```

Пример других корректных пространств имён
```text
  namespace global:dp
  namespace minecraft
  namespace minecrst:functions/print
```
... и не корректных
```text
  namespace global:dp/ # <-- оканчивается на '/', это недопустимо
  namespace minecraft/dp # <-- после первого слово обязано быть ':'
  namespace minecraft: # <-- после ':' должно идти следующее слово
```

---

**И да, комментарии в моём языке обозначаются через '#'. Комментироваться будет всё от '#' до конца строки**

---

## **objective**

---

objective - ключевое слово, которое указывает создать scoreboard в *Minecraft*

---

Например, вы в файле напишите следующее
```text
  objective myscore
```
И что это значит?

Предположим вы создаёте objective в пространстве global:dp
```text
  namespace global:dp

  objective myscore
```

Это означает что в датапаке будет создан следующий scoreboard
```text
  scoreboard objectives add global.dp.myscore dummy
```
Это строка будет добавлена в load.mcfunction файл - который будет запускаться при загрузке мира *Minecraft* или после /reload

---

Как работать с этими objectives будет показано в разделе ниже

---

## **Как выглядит исполняемый код**

---

Я решил что мой DSL должен быть статически типизируемым.

---

### Базовые типы

---

Пока есть следующие базовые типы.

| Тип | Задача |
|---|---|
| score | Это обычная переменная реализованная на scoreboard - через неё вы можете выполнять операции '*', '/', '-', '+', '%', а также '==' , '!=' |
| score_bool | Булевая переменная, в неё вы можете записать true/false. Поддерживает операции '&&', '\|\|' |
| string | Это nbt-переменная ( значит что хранится как data ), Её можно копировать, а также в неё можно присвоить строковый литерал |
| int | Это nbt-переменная, Её также, пока что, можно копировать или присвоить числовой литерал |
| selector | Это на самом деле не-совсем тип, Но работает схожим образом. В него можно записать сырой *Minecraft*-селектор вида @a\[...\] или @s @n @r @p , нужен как для работы с objective а также для вызова фукнции от лица сущности |
| objective | Это особый тип - он объявляется только в глобальном пространстве через objective как рассказано выше. Его также, как и селектор, нельзя передавать в функции не макросом. Нужен при работе со scoreboard |

---

Работать можно с только объявленными переменными:

нельзя просто написать
```text
  a = 5
  a = 4 + a
```
Нужно обязтельно так
```text
  let a : score = 5
  a = 4 + a
```

Что такое let

let это ключевое слово для объявления переменных, выглядит это так
```text
  let <имя переменной> : <тип переменной> = < выражение >
```
Нюансы

Обязательно при создании переменной её нужно инциализировать. Иначе просто вылетит сообщение об ошибке компиляции.

Тип переменной на самом деле указывать нужно не всегда. Компилятор может сам их вывести по инициализатору.

- Например - ***"let a = 5"*** - автоматически выведется тип для переменной а как score
- Или - ***"let b = a"*** - переменная 'b' будет иметь тот же тип что и переменная 'a'
- Но если создавать int от какого-то числа, то его всё же придётся указать - ***"let с : int = 5"*** - если тип не указать, то он выведется как score
- И снова вспоминаем что если написать ***"let x = c"***, то тип будет int. Так как тип инициализатора известен - int
- ***" let d = "Hello world" "*** сам выведется тип string
- ***" let f = @s "*** - у 'f' тип будет selector
- **Результатом всех арифметических операций пока что является score**

## Функции

---

Функция - это такой, объект,который принимает какие значения при вызове, и затем может вернуть какое-то значение ( а может и не вернуть )

Представленные два вида функций - были одной из первых причин создания этого компилятора

---

### def функции

---

Эти функции в конечном итоге превратятся в обычный .mcfunction файл.

Но у них есть пара важных свойств. В отличие от .mcfunction они могут принимать параметры и возвращать какой-то резльтат

---

Создание функции

```text
  def <имя функции> ( <имя параметра> : <тип параметра> , ... ) -> <возвращаемый тип>
  {
    <Ваш код 1>
    <Ваш код 2>
    <Ваш код 3>
  }
```

Например, создадим функцию sum которая складывает два score и возвращает результат
```text
  def sum ( a : score , b : score ) -> score
  {
    let c = a + b # <-- по правилам выше тип 'c' автоматически выведется как score
    return c 
  }
```

Как видите, с помощью ключевого слова return мы указываем, что именно вернёт функция.

Однако наш пример можно улучшить, а именно написать возвращаемое значение сразу
```text
  def sum ( a : score , b : score ) -> score
  {
    return a + b
  }
```
Это будет работать абсолютно также как и первый пример, но переменная 'c' создаваться не будет. От этого нам только лучше

Функции нужны чтобы, не нужно было постоянно копировать один и тот же фрагмент кода. И их можно использовать внутри других функций

```text
  def sum_x_2 ( a : score , b : score ) -> score
  {
    return sum(a,b)*2
  }
```

Функция выше также принимает два score и возвращет score. Но, как видно, она при этом переиспользует внутри себя функцию sum.

***Но есть один важный момент*** - на данный момент разработки функции нельзя вызывать рекурсивно.

---

Однако, нам не всегда нужно чтобы функция что-то возвращала

Такие функции задаются так :

```text
  def <имя функции> ( <имя параметра> : <тип параметра> , ... )
  {
    <Ваш код 1>
    <Ваш код 2>
    <Ваш код 3>
  }
```

Как видно, мы просто не используем **'-> <возвращаемый тип>'** после перечисления параметра фукнции

---

При работе с функциями важно понимать, что все аргументы, которые мы передаём в функцию просто копируются. С маленькими типами это не очень важно, но при работе с большими данными, это стоит учитывать - вызов таких функций может замедлять работу ***Minecraft*** ( но не очень сильно ).

Однако, вы можете вспомнить, что должен существует ещё один тип функций.

---

### inline функции

---

Это функции очень похожи на обычные, но работают по-другому.

По названию, можно догадаться что они подставляются в код. Когда ты вызываешь функцию, объявленную через def, на уровне майнкрафта вызывается команда

/function <function_name>

А inline функции подставляются в место вызова. Т.е туда, где ты её вызываешь, копируется её тело.

Они объявляются следующим образом.

```text
  inline <имя функции> ( <имя параметра> : <тип параметра> , ... )
  {
    <Ваш код 1>
    <Ваш код 2>
    <Ваш код 3>
  }
```

---

***Важно!*** - эти функции **не могут** возвращать значение. И кажется это делает их немного бесполензыми. Но есть методы решающие эту проблему

---


Пример функции sum объявленной через inline

```text
  inline sum ( a : score , b : score )
  {
    a + b
  }

  def main()
  {
    sum(4,5)
  }
```

Стоит заметить что объявленные таким образом как здесь параметры также будут копироваться. Т.е. main при компиляции изменит свой вид:

```text
  inline sum ( a : score , b : score )
  {
    a + b
  }

  def main()
  {
    sum_prefix_a = 4 # sum_prefix_ - выбрано просто для примера. Чтобы вы понимали что к этим переменным inline sum нет доступа извне.
    sum_prefix_b = 5
    sum_prefix_a + sum_prefix_b
  }
```

---

И вы можете понять, что эта функция бессмыслена. Так как она никак не вляет на вызывающий код.

И для inline функций есть специальный синтаксис.

---

вы можете объявить её параметр так


```text
  inline <имя функции> ( <имя параметра> : $ <тип параметра> , ... ) # <-- Обратите внимание на значок '$' - это отсылает нас к майнкрафт-макросам.
  {
    <Ваш код 1>
    <Ваш код 2>
    <Ваш код 3>
  }
```

Переменные , тип которых объявлен со значком $, будут подставлять внутрь это функции.

Рассмотрим тот же пример, но слегка изменённый. Давайте добавим в параметры переменную c $ и типом score

```text
  inline sum ( a : score , b : score , result : $ score )
  {
    a + b
  }

  def main()
  {
    let c = 0
    sum(4,5,c)
  }
```

При компиляции преобразуется в:
```text
  inline sum ( a : score , b : score , result : $ score )
  {
    с = a + b
  }

  def main()
  {
    let c = 0
    sum_prefix_a = 4
    sum_prefix_b = 5
    с = sum_prefix_a + sum_prefix_b
  }
```

Видим что переменные 'a' и 'b' также копируются, а 'c' - подставляется.

Количество подстановочных параметров в inline функции может быть сколько угодно, и они могут смешиваться с копируемыми параметрами, в каком угодно порядке.
